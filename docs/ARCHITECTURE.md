# AI Connection Guard — подготовительная сборка 0.1

Приложение macOS для подготовки выборочной защиты AI-сервисов: Claude, Codex,
Grok, Gemini и любых добавленных сервисов. Эта версия **не включает сетевую
защиту**. Её можно открыть для настройки, но рассчитывать на блокировку трафика
пока нельзя.

## Что работает сейчас

- Приложение в строке меню и окно настроек на русском языке.
- Добавление, изменение, отключение и удаление сервисов.
- Для каждого сервиса: HTTPS-адрес, приложения, CLI и выбранный браузер.
- Выбор программ с проверкой подписи кода; имя файла само по себе не является
  идентификацией. Неподписанные исполняемые файлы не принимаются.
- Сохранение настроек между запусками, импорт и экспорт JSON. Пароли, токены и
  Xray-конфиги не читаются и не копируются.
- Подготовленный режим «Без ограничений · поездка», обратимый выбором защищённого
  режима. Это желаемый режим будущего развёртывания, не состояние защиты Mac.
- Расчёт правил без сетевых запросов: разрешённый локальный прокси, запрет прямых
  соединений, IPv4/IPv6, UDP, неизвестных процессов и изменившейся подписи.
- Подготовка аргументов запуска Chrome, Edge, Brave и Chromium через HTTP-прокси
  с отдельным каталогом данных сервиса. Каталоги и процессы не создаются.

Выбранный браузер защищается целиком: все окна, вкладки и профили. Обычный
профиль не создаёт отдельной сетевой идентификации программы. Если браузер нужен
нескольким сервисам, он остаётся защищаемым, пока включён хотя бы один из них.
Для других браузеров, включая Safari и Firefox, эта версия сохраняет выбор,
но не обещает настроить их прокси автоматически.

Настройки пользователя при ручном запуске сохраняются только по кнопке
«Сохранить настройки» в `~/Library/Application Support/AI Connection Guard/draft.json`.
При повреждённом файле приложение показывает ошибку и запрещает перезапись, пока
пользователь явно не импортирует корректную замену. Экспорт позволяет сохранить
отдельную копию. При отключении всех сервисов защищённая политика считается
неполной; снятие всех ограничений задаётся отдельным режимом поездки.

## Сборка и проверка

Требуются macOS 13+ и Xcode Command Line Tools. Внешних зависимостей нет.

```sh
CLANG_MODULE_CACHE_PATH=/tmp/ai-guard-clang-cache swift test --disable-sandbox --scratch-path /tmp/ai-connection-guard-build
./build-app.sh
```

Результат: `dist/AI Connection Guard.app` и отдельный
`dist/Prepared Extension/ConnectionGuard.Filter.systemextension`.
Скрипт не устанавливает их, не добавляет автозапуск и не запускает программы.
Сборка подписана ad-hoc для локального просмотра, не для развёртывания фильтра.

## Сетевое ядро и границы этой версии

`GuardPolicy` — неизменяемый набор правил на срок работы провайдера.
`FilterProvider` — компилируемый адаптер macOS Network Extension, принимающий
процессы через audit token macOS и проверяющий их подпись. Локальные соединения
имеют явные правила, поскольку macOS исключает loopback из defaultAction.

В защищённом режиме выбранным приложениям разрешён только TCP к заданному
локальному прокси. Процессу Xray разрешён только заданный IP и порт VPS. Приём
на порту прокси разрешён только выбранному процессу туннеля. Прочие
идентифицированные приложения не ограничиваются. Если идентифицировать процесс
не удалось, ядро запрещает соединение, что при реальном развёртывании может
затронуть и другие программы — это нужно проверить на конкретном Mac.

Это защита через явно заданный туннель, а не периодическая геолокация внешнего
IP. IP сервера считается выбранным пользователем доверенным адресом; программа
не определяет его страну. Полный живой путь требует ещё интеграционной работы:

1. Developer ID, разрешение Network Extension, provisioning profile и системное
   одобрение пользователя. Развёртываемая сборка должна получить отдельный
   контроллер установки, включения и отключения фильтра. В текущем приложении
   такого контроллера намеренно нет.
2. Проверенный Xray-конфиг без прямого fallback, запуск и контроль Xray на Mac,
   применение прокси для каждого приложения/CLI и управляемый запуск браузеров.
   Текущая версия рассчитывает параметры и проверяет правила, но туннель не
   запускает и конфигурацию Xray не валидирует.
3. Проверка реальных потоков, существующих сокетов, смены Wi-Fi/Ethernet,
   падения туннеля/провайдера, сна и перезагрузки. Unit-тесты не доказывают
   отсутствие утечек пакетов в macOS.
4. Проверка атрибуции процессов. Подписанные helpers внутри app bundle и
   responsible-app audit token поддержаны. Отделившиеся процессы, внешние
   помощники и общий runtime (`node`, Python, shell) не становятся автоматически
   защищёнными потомками. Их нужно включать отдельно либо дорабатывать
   контроль дерева процессов. Два CLI на одном исполняемом runtime нельзя
   надёжно разделить только по аргументам этим фильтром.

Один защищённый браузер может иметь несколько отдельных каталогов данных для
сервисов, но все его экземпляры попадут под одно сетевое правило. Применение
новой политики требует отдельного управляемого жизненного цикла провайдера;
редактирование файла draft не меняет уже работающие правила. Условие снятия
ограничений должно применяться контроллером явно, а не при ошибке провайдера.

`BuildSafety.networkChangesPermitted` зафиксирован в `false`; вход провайдера
также прекращает выполнение. Изменения этой константы недостаточно для готового
развёртывания. Нельзя интерпретировать эту сборку как уже работающий kill switch.
Закрытие программы сейчас закрывает только редактор. Удалённые задания в облаке
Claude/Codex не отменяются локальным сетевым фильтром.
