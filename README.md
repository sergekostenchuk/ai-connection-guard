# AI Connection Guard

**Сервисы, приложения и браузеры — настройки будущей сетевой защиты в одном окне macOS.**

macOS 13+ · Swift / SwiftUI / AppKit · версия 0.1.0 · интерфейс на русском

> **Статус: подготовительная версия.** Работают редактор настроек и симулятор
> правил. Приложение **не блокирует трафик**, не устанавливает сетевой фильтр,
> не запускает VPN и не меняет текущие подключения. Это ещё не работающий kill switch.

## Для чего

Собрать настройки подключения Claude, Codex, Grok, Gemini и других сервисов в
одном месте: какие приложения и CLI относятся к сервису, какой браузер для него
использовать и какой локальный туннель разрешить.

Будущая сетевая защита рассчитана на явно выбранный туннель: если приложение
пытается соединиться напрямую, такое соединение должно быть запрещено. Программа
не определяет страну внешнего IP. В текущей версии можно подготовить настройки
и рассчитать решение правила, не вмешиваясь в действующую сеть.

| Режим поездки | Сохранение желаемого режима «Без ограничений» |
| Проверка правил | Локальный расчёт для IPv4, IPv6, TCP и UDP |
| Настройки | Сохранение между запусками, импорт и экспорт JSON |
| Реальная блокировка | **Не подключена** |

### Подключение через браузер

Для каждого сервиса можно выбрать браузер. Для поддерживаемых Chromium-браузеров
программа показывает аргументы будущего запуска: отдельный каталог профиля,
локальный прокси, отключение QUIC и исключение прямого обхода прокси для loopback.
Браузер при этом не запускается, профиль не создаётся.

**Сетевое правило относится ко всему браузеру — ко всем окнам, вкладкам и
профилям.** Отдельный профиль разделяет данные сайтов, но не создаёт отдельного
сетевого приложения. Поэтому для AI-сервисов стоит выделить отдельный браузер.
Если один браузер выбран у нескольких сервисов, он остаётся в списке защиты,
пока включён хотя бы один из них.

Safari, Firefox и другие браузеры можно сохранить в карточке, но автоматическая
подготовка параметров прокси для них в этой версии не реализована.

### Проверка правила без подключения

Выберите программу, IP, порт и протокол — симулятор покажет решение ядра.
Неполные настройки отображаются явно. Проверка не отправляет сетевой запрос и
не подтверждает отсутствие утечек на реальном Mac.

## Установка через npm

npm-пакет содержит исходники и команду сборки нативного приложения. Для этой
команды нужны **macOS 13+, Node.js 20+ и Swift 5.9+ из Xcode/Command Line Tools**.

```sh
# Собрать и скопировать приложение в ~/Applications
npx ai-connection-guard install

# Или только собрать в ./dist
npx ai-connection-guard build
```

После установки откройте `.app` вручную из `~/Applications`. При обычном
`npm install` ничего не собирается и не запускается: в пакете нет install hooks.
Команда не включает автозапуск, не устанавливает системный фильтр и не меняет
сетевые настройки. Существующая копия приложения не перезаписывается: перед
обновлением завершите её и переместите в другое место.

[Пакет на npm](https://www.npmjs.com/package/ai-connection-guard) ·
`npx ai-connection-guard --help`

## Собрать и открыть

Нужны macOS 13+ и Swift 5.9+ из Xcode или совместимых Command Line Tools.
Сторонних Swift-пакетов нет.

```sh
git clone https://github.com/sergekostenchuk/ai-connection-guard.git
cd ai-connection-guard
./build-app.sh
open "dist/AI Connection Guard.app"
```

Скрипт только собирает файлы. Он не устанавливает программу, не меняет прокси,
не добавляет автозапуск и не запускает фильтр. Сборка выполняется для архитектуры
текущего Mac; локально проверена на Apple Silicon.

Результаты:

- `dist/AI Connection Guard.app` — приложение для настройки.
- `dist/Prepared Extension/ConnectionGuard.Filter.systemextension` — отдельно
  собранный, неактивный провайдер. Он не входит в приложение и не устанавливается.

Используется локальная ad-hoc подпись. Developer ID и нотариализация в этой
версии не настроены; системный фильтр для развёртывания ещё не подготовлен.

## Как пользоваться

1. Откройте настройки через значок щита в строке меню.
2. Выберите готовый сервис или нажмите **«Добавить сервис»**.
3. Добавьте приложения/CLI и при необходимости браузер.
4. В **«Настройках туннеля»** укажите будущий локальный прокси, исполняемый файл
   Xray и адрес сервера. Реальные конфиги Xray здесь не импортируются.
5. Выберите желаемый режим: защищённый или **«Без ограничений · поездка»**.
6. Нажмите **«Сохранить настройки»**. Кнопка применения защиты пока отключена.

Настройки сохраняются в
`~/Library/Application Support/AI Connection Guard/draft.json`.
Импорт и экспорт позволяют переносить их между установками. JSON содержит
пути выбранных программ и адрес сервера; учитывайте это, если делитесь файлом.
При повреждённом файле приложение показывает ошибку и не перезаписывает его
автоматически — можно импортировать корректную копию.

## Что ещё нужно для рабочей защиты

- Контроллер установки, включения и снятия системного фильтра; Developer ID,
  entitlement Network Extension, provisioning profile и одобрение macOS.
- Интеграция локального Xray: проверка конфигурации, запуск, контроль состояния,
  настройка прокси приложений и управляемый запуск браузеров.
- Проверка реального трафика при смене сети, падении туннеля, сне и перезагрузке,
  а также уже открытых соединений и вспомогательных процессов.

Сейчас `BuildSafety.networkChangesPermitted` зафиксирован в `false`. Простого
изменения этой константы недостаточно для получения рабочей защиты.
Полная архитектура, модель идентификации процессов и известные ограничения —
в [техническом описании](docs/ARCHITECTURE.md).

## Разработка

```sh
CLANG_MODULE_CACHE_PATH=/tmp/ai-guard-clang-cache \
  swift test --disable-sandbox --scratch-path /tmp/ai-connection-guard-tests
```

Команды npm-обёртки проверяются отдельно: `npm test`. У них нет внешних
зависимостей.

33 unit-теста покрывают правила маршрута, IPv4/IPv6, UDP, подписи процессов,
общий браузер нескольких сервисов, режим поездки, сохранение и повреждённые
настройки. Они проверяют программную логику, а не работу установленного фильтра.

| Каталог | Назначение |
| --- | --- |
| `Sources/ConnectionGuard` | Приложение и интерфейс |
| `Sources/ConnectionGuardCore` | Модели, идентификация кода, правила и сохранение |
| `Sources/ConnectionGuardFilter` | Адаптер Network Extension |
| `Tests/ConnectionGuardCoreTests` | Тесты ядра |
| `Resources` | Метаданные и шаблон entitlement фильтра |

Ошибки и предложения можно отправлять через Issues, изменения — через Pull
Request. Для изменений правил добавляйте тест на соответствующий сценарий.
Не прикладывайте токены, ключи, реальные VPN-конфиги или личные файлы настроек.
